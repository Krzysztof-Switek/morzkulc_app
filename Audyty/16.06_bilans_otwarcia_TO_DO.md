## Uwagi
- **Kolejność jest istotna:** deploy → import bilansu (A) → reconcile (E) → zasilenie arkusza (D) → import godzinek (C) → rejestracja.
- Szczegółowe liczniki są w **logach funkcji** (`firebase functions:log`); `service_jobs` trzyma tylko status + `lastError`.
- Zakładka „Godzinki 2026 i korekty" służy też do **bieżących korekt** do końca IX 2026: dodajesz nowy wiersz (np. `-2`), oznaczasz „Zatwierdzone=TAK", ponawiasz krok 7 — import utworzy nowy rekord pod właściwym uid (albo `hist_{email}`, jeśli osoba jeszcze niezarejestrowana).
- **Rollback bilansu:** kolekcja `users_opening_balance_26` jest odtwarzalna — można ją wyczyścić i zaimportować ponownie. Rekordy w `godzinki_ledger` z importu mają `approvedBy="transition_import"` / `"opening_balance"` (do identyfikacji).
