## A. Box „Klub" w profilu użytkownika

Nowa sekcja w panelu profilu (`#/home/profile`) z ogólnymi informacjami klubowymi,
zbudowana z **istniejących** danych (synch. z arkusza), bez nowego modelu wprowadzania.

- **Endpoint** `GET /api/klub` — `functions/src/api/getKlubInfoHandler.ts`
  (eksport `getKlubInfo` w `index.ts`, rewrite w `firebase.json`).
- **Zawartość:** Zarząd (funkcje prezes/skarbnik/sprzętowiec/szkoleniowiec →
  nazwy z `users_active`, kontakt przez skrzynkę funkcyjną), KR (`rola_kr`),
  Konto klubowe + bank (`setup/vars_members.vars`), **Stan konta / gotówki**
  (`stan_konta`, `stan_kasy_gotówkowej`) — **tylko KR/Zarząd**, gating po stronie
  serwera. Linki statut/regulamin/klucze pojawią się po dodaniu zmiennych do SETUP.
- **Frontend:** box renderowany w karcie profilu (`public/core/render_shell.js`,
  `renderHomeProfile`), style w `public/styles/start.css`. Numer konta: l. pojedyncza
  grupowana (NRB), „Bank: numer", przycisk Kopiuj.
- **Naprawa precyzji numeru konta:** `parseSetupValue` w
  `functions/src/service/tasks/setupSyncFromSheet.ts` robił `Number()` na 26-cyfrowym
  numerze → zapis naukowy. Fix: round-trip guard `String(n) === s` (długie ID zostają
  stringiem). **Wymaga ponownego `setup.syncFromSheet`**, by wartość w Firestore się
  poprawiła.
- **Bezpieczeństwo finansów:** pola finansowe wysyłane wyłącznie dla KR/Zarządu
  (rola z `users_active/{uid}`). Cache boxa w sessionStorage **usunięty** — groził
  wyciekiem danych finansowych następnemu userowi w tej samej karcie (logout nie
  czyści sessionStorage); `hardResetUi` dodatkowo czyści `klubInfoCache*`.
- **Czyszczenie martwego kodu (.gs):** usunięte `parseSetupValue_`, `readSetupVars_`,
  `readAppSetupModules_`, `isDateObject_`, `formatTimeHHMM_` w
  `appscript/członkowie sympatycy SKK/{setup_sync,common_helpers}.gs` (sync robi
  backend, te funkcje były martwe).
- **Test:** `functions/scripts/checkKlubFinanceLeak.js` — potwierdza, że żadne konto
  spoza KR/Zarządu nie dostaje finansów (na prod: 36 kont spoza, 0 wycieków).

## B. Panel Zarząd — zakładki + raporty

`public/modules/admin_pending_module.js` — dwie zakładki:
- **Administracja** (domyślna) — dotychczasowa treść (`/api/admin/pending`).
- **Raporty** — launcher kafelkowy.

### Launcher (kafelki + szukajka → szczegół)
Framework w `public/modules/raporty/`:
- `reports_panel.js` — `renderReportsPanel`: kafelki pogrupowane wg kategorii (3 w
  rzędzie; 2 na <380px) + szukajka → szczegół z „← Raporty". Dane renderuje tylko
  jeden raport naraz. **Dodanie raportu = nowy plik + wpis w `registry.js`.**
- `registry.js` — tablica `REPORTS`.
- Style launchera `.reportLauncher/.reportTile/.reportGrid/...` w `base.css`.
- Kafelki bez opisu (sam tytuł).

### Raport 1 — „Wypożyczenia sprzętu" (`gear_rentals.js`)
- `GET /api/admin/reports/gear-rentals` (`getAdminGearRentalsHandler.ts`).
- Zakres kroczący: Aktualnie wypożyczony (domyślny) / miesiąc / semestr / rok /
  zakres dat. Nakładanie okresu na `gear_reservations` bez indeksu złożonego
  (`endDate>=from` + filtr w pamięci `status=="active" && startDate<=to`).
- Filtr kategorii = checkboxy (po stronie klienta). **Selektor użytkownika**
  (nazwisko/ksywa/mail, datalist; pole `userNick` z backendu).
- Pozycje sprzętu w **l. pojedynczej** („Kajak 11", „Kamizelka 2") — mapa
  `CATEGORY_NOUN` po stronie klienta.

### Raport 2 — „Najbardziej aktywni" (`member_activity.js`)
- `GET /api/admin/reports/member-activity` (`getAdminMemberActivityHandler.ts`).
- Ranking członków wg wypracowanych godzinek. Zakresy: miesiąc / **semestr
  (domyślny)** / rok / zakres dat. Suma `amount` z `godzinki_ledger`
  (`type="earn" && approved && grantedAt` w zakresie; tylko earn ma grantedAt →
  brak indeksu złożonego).

### Raport 3 — „Składki" (`member_dues.js`)
- `GET /api/admin/reports/member-dues` (`getAdminMemberDuesHandler.ts`).
- Populacja: **pełni członkowie** (`rola_czlonek/zarzad/kr`). Status składek z
  `contributionsPaidUntil` (paid = data ≥ dziś); saldo z `computeBalance`;
  **uprawniony do głosowania = opłacone składki && dodatnie saldo godzinek**.
- Widok: select Wszyscy / Zaległości / Opłacone / Uprawnieni do głosowania +
  tabela (Osoba / Składki do / Saldo / Głosowanie) + podsumowanie liczbowe.

### Reguły biznesowe raportów członkowskich (WAŻNE)
1. **Tylko zarejestrowani w aplikacji** — `isRegistered` = profil z imieniem i
   nazwiskiem (`profile.firstName && profile.lastName`). Odsiewa puste konta SSO
   (zalogowane raz, bez ukończonej rejestracji; mają `firstLoginAt`+`status_aktywny`,
   ale brak profilu — np. misiek4u). Zastosowane w member-activity i member-dues.
   Efekt: składki 24→22.
2. **Pomijamy bilans otwarcia** w godzinkach — marker
   `godzinki_ledger.approvedBy === "opening_balance"` (creditOpeningBalance,
   reason „Bilans otwarcia"; import przejściowy ma inny marker → NIE wykluczany).
   Zastosowane w member-activity (suma) i member-dues (saldo do głosowania).
   Efekt: ranking semestru 25→5 (Marcin Korbas 330 h to były godziny OB).

### Eksport PDF (wszystkie raporty)
- Przycisk „📄 Pobierz PDF" w nagłówku szczegółu (`reports_panel.js`) → natywny
  `window.print()` + `body.printingReport` + arkusz `@media print` w `base.css`
  izolujący `#reportDetailBody` (nagłówek „SKK Morzkulc — <tytuł>" + data, ukryte
  kontrolki/przyciski/checkboxy, czytelne kolory na białym). Zero zależności.
  W dialogu: „Zapisz jako PDF". Działa też na telefonie i dla przyszłych raportów.

### Inne
- Stary przycisk nawigacji „Raporty zarządu" (`modul_9` w `setup/app.modules`) —
  zbędny, użytkownik **wyłączył go w arkuszu APP_SETUP** (aktywny=FAŁSZ + sync).

## D. Stan wdrożenia + checklista

**Wdrożone (deploy funkcji + ustawiony public invoker — potwierdź w konsoli Cloud Run):**
- `getKlubInfo`, `getAdminGearRentals`, `getAdminMemberActivity` (wersja sprzed
  zmian OB/registered) — z dużego deployu funkcji.

**NIE wdrożone / wymaga redeployu:**
- `getAdminMemberActivity` — **zmieniony** (wykluczenie bilansu otwarcia + filtr
  zarejestrowanych) → konieczny redeploy.
- `getAdminMemberDues` — **nowa funkcja** → deploy + **public invoker** w Cloud Run.
- **Hosting** — cały frontend raportów (launcher, kafelki 3-w-rzędzie, raporty
  member-activity/member-dues, selektor użytkownika, l. pojedyncza, PDF, box Klub).

**Komenda wdrożenia:**
```
firebase deploy --only functions:getAdminMemberActivity,getAdminMemberDues,hosting
```
Po deployu: ustaw publiczny invoker Cloud Run dla nowych funkcji (jak inne `/api/*`):
`getklubinfo`, `getadmingearrentals`, `getadminmemberactivity`, `getadminmemberdues`
(`reference_function_invoker_state` — pewne źródło to konsola Cloud Run).

**Osobno (dane):** ponowny `setup.syncFromSheet`, by numer konta zapisał się jako
pełny string (po poprawce parseSetupValue). Dodanie linków statut/regulamin/klucze =
wiersze w SETUP.
