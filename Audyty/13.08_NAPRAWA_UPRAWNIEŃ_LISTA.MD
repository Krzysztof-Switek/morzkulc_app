- Wywołać (fire-and-forget, non-fatal, wzorem `enqueueKmHistoricalMerge`) w DWÓCH miejscach gałęzi `EXISTING USER`:

### 2.4 Nowy task `users.reconcileWorkspaceGroups` — rekoncyliacja okresowa (główny mechanizm zamykający lukę na stałe)

Nowy plik: `functions/src/service/tasks/reconcileWorkspaceGroups.ts`, wzorowany na `functions/src/service/tasks/reconcileOpeningBalance.ts` (tryb hurtowy/punktowy) i `functions/src/service/tasks/groupsDiagnose.ts` (efektywne czytanie `listMembersDetailed` per-grupa zamiast per-user).

**Payload:** `{ dry?: boolean; email?: string }`.

**Tryb hurtowy:**
1. Zbuduj `managedGroups` = suma grup z `setup/app.roleMappings[*].groups` + `config.listaGroupEmail`.
2. Dla każdej grupy z `managedGroups` — **jedno** wywołanie `workspace.listMembersDetailed(group)` (mapa email→rola), zamiast N×M zapytań per-user.
3. Pobierz wszystkich `users_active`.
4. Dla każdego użytkownika policz oczekiwany stan przez wspólny moduł (2.1):
   - `status_key === "status_aktywny"` → oczekiwana rola/członkostwo wg `role_key` (jak dziś).
   - `status_key !== "status_aktywny"` (zawieszony/skreślony) → **oczekiwane: BRAK członkostwa w żadnej zarządzanej grupie, w tym `lista@`** (decyzja: TAK, obejmujemy usuwanie dostępu — patrz ustalenie z użytkownikiem).
5. Porównaj z żywym stanem Directory (krok 2) — **nie** z markerami Firestore (niewiarygodne, patrz 1.2 — wariant "kursant→awans" i wariant "skasowany/odtworzony dokument").
6. Skoryguj różnice: `addMemberToGroup`/`removeMemberFromGroup` (obie idempotentne, już istnieją w `googleWorkspaceProvider.ts`).
7. Zapisz snapshot wyniku do `service_diag/workspaceGroupsReconcile` (wzorem `groupsDiagnose` → `service_diag/groups`) — lista korekt (email, grupa, before→after) do audytu.

**Tryb punktowy (`payload.email`):** ta sama logika dla jednej osoby — cel wywołań z `registerUserHandler.ts` (2.2).

Zarejestrować w `functions/src/service/registry.ts` (import + wpis w tablicy `tasks`).

**Scheduler** w `functions/src/index.ts`, obok `usersSyncRolesDaily`:
```ts
export const usersReconcileWorkspaceGroupsDaily = onSchedule(
  {schedule: "40 4 * * *", timeZone: "Europe/Warsaw"},
  async () => {
    const result = await runTaskById("users.reconcileWorkspaceGroups", {});
    logger.info("usersReconcileWorkspaceGroupsDaily: done", result as unknown as Record<string, unknown>);
  }
);
```
O 04:40 — po `usersSyncRolesDaily` (04:30), przed `eventsSyncSheetDaily` (04:45).

To jest mechanizm odporny na WSZYSTKIE przyszłe luki: nawet jeśli ktoś doda kolejną ścieżkę zmiany `role_key`/`status_key` i zapomni wywołać synchronizację, rekoncyliacja naprawi to samodzielnie w ciągu maksymum 24h, bo porównuje z żywym stanem Directory, a nie z markerami czy wykrytą zmianą.
