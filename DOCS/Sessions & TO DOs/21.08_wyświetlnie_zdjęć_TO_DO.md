# Wskaźnik ładowania przy przełączaniu zdjęć kajaka

**Status: WDROŻONE na prod (morzkulc-e9df7) 21.08.2026, POTWIERDZONE przez usera**
(test na Slow 3G w DevTools — kropki działały poprawnie).

Poprawki po wdrożeniu:
1. **Bug widoczności overlaya** — `.gearPhotoLoading` miało `display: grid` wprost w
   CSS, co nadpisywało domyślną regułę przeglądarki `[hidden] { display: none }`
   (style autora zawsze biją domyślne UA, niezależnie od specyficzności) — overlay
   był widoczny cały czas, niezależnie od stanu ładowania. Naprawione przez
   przełączenie na istniejącą w projekcie klasę `.hidden { display: none !important; }`
   (ten sam wzorzec co `modalPrevBtn.classList.add("hidden")` w tym samym pliku)
   zamiast natywnego atrybutu `hidden`.
2. **Zamiana pulsujących kropek na kółko** (feedback usera po teście) — klasyczny
   obracający się spinner (`border` + `@keyframes gearSpin { to { transform:
   rotate(360deg); } }`) zamiast trzech kropek reużywających `dotPulse`.

Dorzucona też poprawka `data-loaded-cover-url` (patrz sekcja "Dodatkowo, w tym
samym fixie") — lightbox otwiera się na ostatnio przesuniętym zdjęciu z karty.

## Kontekst

Przy przewijaniu zdjęć kajaka (swipe na karcie kajaka ORAZ w pełnoekranowej
przeglądarce/lightbox) licznik "2/5", "3/5" zmienia się natychmiast, ale samo
zdjęcie — jeśli nie zdążyło się wczytać (wolna sieć) — nadal pokazuje POPRZEDNIE
zdjęcie, bez żadnego wskaźnika ładowania. Efekt: na wolnej sieci wygląda, jakby
kajak miał tylko jedno zdjęcie. User zaproponował dodanie komunikatu ładowania,
wzorem istniejącego spinnera "Morzkulc myśli".

Zweryfikowane (2 agenty: Explore + Plan, pełny odczyt kodu):
- Bug istnieje w DWÓCH miejscach w `public/modules/gear_module.js`: swipe na
  karcie (linie 1338-1382, licznik `.gearImgCounter`) i lightbox `showPhotoAtIdx`
  (linie 1162-1178, licznik `#gearModalCounter`). W obu: `imgEl.src = url`
  odpala async fetch, kolejna linijka od razu nadpisuje tekst licznika — brak
  `onload`/`onerror`, brak spinnera.
- Natywne zachowanie `<img>` samo utrzymuje POPRZEDNIE zdjęcie widoczne, dopóki
  nowe się nie wczyta — to już działa za darmo, nie trzeba nic dodawać, żeby
  spełnić "zostaw stare zdjęcie widoczne".
- Istniejący wzorzec pulsujących kropek: `.thinking .dot` + `@keyframes dotPulse`
  (`public/styles/base.css:118-135`) — globalny keyframe, dostępny wszędzie bez
  importu (base.css ładowany przed gear.css w app.css).
- Oba kontenery zdjęć są już `position: relative` z istniejącymi overlayami
  wewnątrz (`.gearImgCounter`, `.gearImgLabel` w `.gearImgPh`;
  `.gearImgNavBtn` w `.gearImgViewer`) — gotowe miejsce na kolejny overlay.
- Brak guardu przeciw nakładającym się async odpowiedziom przy szybkim
  wielokrotnym swipe'owaniu (mitygowane dziś tylko przypadkowo przez natywne
  zachowanie `<img src>`) — nowy kod dodaje jawny licznik generacji.

## Rozwiązanie

**1. CSS** — `public/styles/gear.css`, nowa klasa `.gearPhotoLoading` (przy
`.gearImgCounter`, ok. linii 353): pełny overlay (`position:absolute; inset:0`),
półprzezroczyste tło `rgba(0,0,0,0.35)` (jak `.gearImgLabel` — jednocześnie
przyciemnia stare zdjęcie i jest tłem pod kropkami), 3 kropki `.dot` reużywające
`dotPulse`, `pointer-events: none` (żeby nie blokować przycisków nawigacji w
lightboxie). Pokazywanie/ukrywanie przez atrybut `hidden` — bez tranzycji/fade,
zgodnie z istniejącym wzorcem `.gearImgCounter` (`counter.hidden = false` bez
animacji) — brak potrzeby crossfade, user prosił o wskaźnik ładowania, nie o
animację.

**2. Markup** — `public/modules/gear_module.js`:
- Karta kajaka (`.gearImgPh`, linie 1670-1679): dopisać jako ostatnie dziecko
  `<div class="gearPhotoLoading" hidden aria-hidden="true"><span class="dot">.</span><span class="dot">.</span><span class="dot">.</span></div>`.
  Tylko `renderKayakCard` — inne karty sprzętu nie mają swipe/licznika.
- Modal (`.gearImgViewer`, linie 229-233): analogicznie, z `id="gearModalLoading"`
  (pojedyncza instancja jak reszta elementów modala), dodać
  `const modalLoadingEl = viewEl.querySelector("#gearModalLoading");` obok
  pozostałych `modal*El` (linia ~451).

**3. Logika** — nowy współdzielony helper w `gear_module.js` (po `PLACEHOLDER_SVG`,
linia 18):
```js
function loadPhotoWithOverlay({ imgEl, overlayEl, url, bumpGen, currentGen, onError }) {
  const myGen = bumpGen();
  if (overlayEl) overlayEl.hidden = false;
  imgEl.onload = () => {
    if (currentGen() !== myGen) return;
    if (overlayEl) overlayEl.hidden = true;
  };
  imgEl.onerror = () => {
    if (currentGen() !== myGen) return;
    if (overlayEl) overlayEl.hidden = true;
    if (imgEl.getAttribute("src") !== PLACEHOLDER_SVG) imgEl.setAttribute("src", PLACEHOLDER_SVG);
    if (typeof onError === "function") onError();
  };
  imgEl.src = url;
}
```
Wspólna tylko logika "generacja + overlay + onload/onerror" — reszta (odczyt DOM,
tekst licznika, stan przycisków prev/next) zostaje osobno w obu miejscach, bo
kształt danych jest inny (per-kajak `photoState` Map vs. pojedynczy modal).

- **Swipe na karcie** (linie 1370-1381): dodać `gen: 0` do wpisu `photoState`
  (miejsce tworzenia, linia 897) i wywołać helper zamiast bezpośredniego
  `imgEl.src = ...`, z `bumpGen: () => ++state.gen`, `currentGen: () => state.gen`.
  Licznik tekstowy (`.gearImgCounter`) zostaje aktualizowany od razu, bez zmian.
- **Lightbox** (`showPhotoAtIdx`, linie 1162-1178): dodać `let modalPhotoGen = 0;`
  obok `allPhotoUrls`/`currentPhotoIdx` (linia 1158), zastąpić
  `modalImgEl.setAttribute("src", ...)` wywołaniem helpera z
  `onError: () => { modalHintEl.textContent = "Brak zdjęcia."; }`. Istniejący
  `modalImgEl.onerror` (linia 1180, obsługujący błąd PRZED pierwszym
  `showPhotoAtIdx`) zostaje nietknięty — zwykłe nadpisanie właściwości przy
  pierwszym swipe'u przejmuje kontrolę automatycznie.

**Dodatkowo, w tym samym fixie** (potwierdzone z userem — to jedna linijka w
dokładnie tym handlerze, który i tak edytujemy, więc nie ma sensu odkładać):
`data-loaded-cover-url` nie jest dziś aktualizowany przy swipe'owaniu karty, więc
otwarcie lightboxa po przesunięciu karty i tak otwiera okładkę (index 0), nie
ostatnio przesunięte zdjęcie. Naprawa: w handlerze swipe'a na karcie (linie
1370-1381), zaraz po przeliczeniu `state.idx`, dopisać
`btn.setAttribute("data-loaded-cover-url", state.urls[state.idx]);` — lightbox
otworzy się wtedy na zdjęciu, na którym user aktualnie zatrzymał się na karcie.

## Weryfikacja

Brak testów automatycznych dla `public/` — weryfikacja ręczna:
1. Chrome DevTools → Network → "Disable cache" + throttling **Slow 3G** (Fast 3G
   może wczytać zbyt szybko, żeby zobaczyć overlay).
2. Swipe na karcie kajaka z kilkoma zdjęciami: licznik zmienia się natychmiast,
   overlay z kropkami pojawia się od razu NA starym zdjęciu (nie pusty
   placeholder), znika dokładnie gdy nowe zdjęcie się doładuje.
3. To samo w lightboxie: swipe dotykiem, strzałki prev/next, klawiatura ←/→.
4. Szybkie wielokrotne swipe'y (4-5 zdjęć pod rząd) — overlay nie może "zawiesić
   się" widoczny, finalne zdjęcie musi zgadzać się z finalnym licznikiem.
5. Zablokować jeden request zdjęcia w DevTools (Block request URL) — overlay musi
   zniknąć (nie wisieć w nieskończoność), zdjęcie spada do `PLACEHOLDER_SVG`.
