# Prompt do odtworzenia stylu (design system) w innym projekcie

Wklej poniższy blok do Claude w docelowym projekcie. Kalendarz rezerwacji jest
już przeniesiony osobno (inny prompt) — to dotyczy reszty: palety kolorów
jasny/ciemny, przełącznika motywu, nawigacji, kart, przycisków, formularzy i
kafelków (dużych na stronie głównej + mniejszych w sekcjach wewnętrznych).

---

Chcę wdrożyć w tym projekcie dokładnie ten sam system wizualny (design system)
opisany poniżej — dostosuj nazwy klas/zmiennych do konwencji tego projektu, ale
zachowaj wygląd, proporcje i mechanikę 1:1.

## Filozofia stylu

Ciemny motyw jako domyślny, jasny jako opcja (nie odwrotnie). Wszystko oparte
na garści zmiennych CSS (`:root`), zero hardkodowanych kolorów w komponentach —
każdy komponent czyta `var(--tekst)`, `var(--border)` itd. Każda "uniesiona"
powierzchnia (karta, kafelek, plakietka, chip) używa TEJ SAMEJ formuły:
1px ramka w kolorze `--border` + bardzo subtelny gradient/tło (biały ~3-6%
przezroczystości w dark, ciemny ~1-4% w light) + zaokrąglone rogi. To jedna
reguła stosowana konsekwentnie do dziesiątek komponentów zamiast osobnego
stylu na każdy — dzięki temu nowy komponent "pasuje" automatycznie, jeśli
trzyma się tej formuły.

## 1. Mechanizm przełączania motywu

Atrybut `data-theme` na `<html>`, wartości `"dark"` (domyślna, brak potrzeby
jawnego atrybutu — `:root` bez selektora już jest ciemny) / `"light"` /
`"auto"` (respektuje `prefers-color-scheme` systemu). Zapisywane w
`localStorage`. Przycisk przełącznika to zwykły emoji ☀️/🌙, bez ikon SVG.

```js
const STORAGE_KEY = "app_theme"; // "dark" | "light" | "auto"

function getInitialTheme() {
  const saved = String(localStorage.getItem(STORAGE_KEY) || "").trim();
  if (saved === "light" || saved === "dark" || saved === "auto") return saved;
  return "dark"; // domyślnie ciemny
}

function applyTheme(mode) {
  document.documentElement.setAttribute("data-theme", mode);
  updateToggleUi(mode);
}

function updateToggleUi(mode) {
  const btn = document.getElementById("themeToggle");
  if (!btn) return;
  const isLight = mode === "light";
  btn.setAttribute("aria-label", isLight ? "Przełącz na motyw ciemny" : "Przełącz na motyw jasny");
  btn.title = isLight ? "Ciemny" : "Jasny";
  btn.textContent = isLight ? "🌙" : "☀️";
}

function toggleTheme() {
  const current = document.documentElement.getAttribute("data-theme") || "dark";
  const next = current === "light" ? "dark" : "light";
  localStorage.setItem(STORAGE_KEY, next);
  applyTheme(next);
}

(function initTheme() {
  applyTheme(getInitialTheme());
  window.addEventListener("DOMContentLoaded", () => {
    const btn = document.getElementById("themeToggle");
    if (!btn) return;
    btn.addEventListener("click", toggleTheme);
  });
})();
```

## Podsumowanie zasad do zastosowania w nowych komponentach

1. Zero kolorów "na sztywno" poza stałymi stanami (ok/warn/danger/konflikt) —
   wszystko inne przez zmienne z sekcji 2.
2. Każda uniesiona powierzchnia = `border:1px solid var(--border)` + delikatny
   gradient/tło (jaśniejsze w dark ~3-8% białego, ciemniejsze w light ~1-4%
   czerni) — nigdy płaski jednolity kolor tła bez tej ramki.
3. Ikony zawsze liniowe SVG 24×24 (duże) albo 20×20 (małe), `stroke="currentColor"`,
   `stroke-width="2"`, zaokrąglone zakończenia — nigdy wypełnione/kolorowe ikony.
4. Mobile jest pierwszorzędny: siatki zaczynają od układu mobilnego i **dodają**
   kolumny na szerszym ekranie (`@media (min-width: ...)`), nie odwrotnie.
5. Wysokie kontenery (nav, modal) na mobile świadomie zamieniają zachowanie
   (fixed bottom bar, bottom-sheet) zamiast tylko skalować się w dół.
