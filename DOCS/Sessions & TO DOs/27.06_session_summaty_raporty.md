## B. Cztery raporty

### 1. Wypożyczenia sprzętu (`gear_rentals.js`) — kat. Sprzęt
`GET /api/admin/reports/gear-rentals` (`getAdminGearRentalsHandler.ts`).
Zakres kroczący: Aktualnie wypożyczony (domyślny)/miesiąc/semestr/rok/zakres dat
(nakładanie na `gear_reservations`, `endDate>=from` + filtr `status=="active" &&
startDate<=to`). Checkboxy kategorii (filtr po stronie klienta). **Selektor
użytkownika** (nazwisko/ksywa/mail, pole `userNick`). Pozycje w **l. pojedynczej**
(„Kajak 11").

### 2. Najbardziej aktywni (`member_activity.js`) — kat. Członkowie
`GET /api/admin/reports/member-activity` (`getAdminMemberActivityHandler.ts`).
Ranking wg **godzin WYPRACOWANYCH w wybranym oknie** (suma approved `earn` z
`grantedAt` w zakresie). Zakresy miesiąc/**semestr (domyślny)**/rok/custom. Kolumna
**„Godziny w okresie"** + hint, że to nie saldo.

### 3. Składki i uprawnieni do głosowania (`member_dues.js`) — kat. Członkowie
`GET /api/admin/reports/member-dues` (`getAdminMemberDuesHandler.ts`).
Pełni członkowie (rola_czlonek/zarzad/kr). Status składek z `contributionsPaidUntil`
(paid = data ≥ dziś); **saldo = `computeBalance` (wszystkie rekordy)**; **uprawniony do
głosowania = opłacone składki && saldo > 0** (zero wykluczone). Widok: Wszyscy/
Zaległości/Opłacone/Uprawnieni + tabela (Osoba/Składki do/**Saldo godzinek**/Głosowanie)
+ podsumowanie. Kolory `.duesOk/.duesBad`.

### 4. Aktywność użytkownika (`user_activity.js`) — kat. Członkowie
`GET /api/admin/reports/user-activity` (`getAdminUserActivityHandler.ts`).
Admin wpisuje frazę → **pełna historia godzinek (przyznane + wydane) danego usera jak
w jego aplikacji** (saldo z `computeBalance` + tabela helperami z `godzinki_module.js`,
klasy `.godzinki*`). Zakresy miesiąc/**semestr**/rok/custom (filtr historii po
`createdAt`). **Wyszukiwanie po e-mailu / nazwisku / ksywie** (param `query`): pełny
e-mail = dokładne dopasowanie; inaczej skan `users_active` + substring; >1 trafień →
klikalne kafelki kandydatów. Hint: „Szukaj po e-mailu, nazwisku lub ksywie".

## C. Reguły biznesowe godzinek (ostateczne)

1. **Raporty członkowskie tylko na zarejestrowanych** (`isRegistered` = profil z imieniem
   i nazwiskiem; odsiewa puste konta SSO, np. misiek4u).
2. **Bilans otwarcia zarejestrowanych LICZY SIĘ normalnie** — nigdzie nie wykluczany
   (wcześniej błędnie wykluczałem `approvedBy=="opening_balance"` — usunięte).
3. **Dwie różne metryki godzin** (to NIE rozjazd): „Najbardziej aktywni" = godziny
   WYPRACOWANE w oknie (kolumna „Godziny w okresie"); „Składki"/profil/„Aktywność
   użytkownika" = bieżące **saldo** (`computeBalance`). Dla osoby z earnem poza oknem
   lub ze spendami liczby się różnią (Barbara Duda: aktywność semestr 11 vs saldo 13).
4. Saldo wszędzie = `computeBalance(godzinki_ledger)` = bilans otwarcia + korekty/
   zgłoszenia (`godzinki.importTransitionFromSheet`) + zgłoszenia w apce.

## D. Remediacja bilansu otwarcia (WYKONANA na prod 27.06)

Problem: pula OB nie powstała w `godzinki_ledger` dla części członków (kredyt OB
czytał puste pole przy rejestracji). Karolina −115 zamiast 14.

Źródło BO: kolekcja `users_opening_balance_26`, pole „Godzinki Bilans otwarcia01.04.2026"
(`getObHours`). Naprawa istniejącym taskiem **`opening.reconcile`** (`reconcileOpeningBalance.ts`)
— tworzy/koryguje pulę OB z kolekcji. Wykonano hurtowo (po dry-run i akceptacji):
**8 nowych pul, 26 odświeżonych, matched=31, errors=0**, idempotentne. Karolina → 14;
żadne saldo nie spadło. Skutek: „Składki" głosujący wzrósł, „Najbardziej aktywni"
(np. Marcin 330, Jakub 384) — wszystko spójne z profilem.

Brzegowe (poza naprawą): Fundacja Ucho (brak w BO26), Łukasz Mielicki (puste OB),
Barbara Duda (BO26 = −19, ujemne → niekredytowane).
