## 2. Jak działa bramka rezerwacji kursanta (kod wdrożony = lokalny)

### 2.1 Frontend
`ctx.kursWypozycza` z `GET /api/setup` steruje **wszystkimi** przyciskami „Rezerwuj" naraz
(`gear_module.js:858-878`, `render_shell.js` — kafelek i sekcja „Moje rezerwacje").
`kursWypozycza=false` → przyciski nieaktywne we wszystkich kategoriach.

### 2.2 `GET /api/setup` (`functions/src/index.ts:407-426`)
Dla realnego kursanta `kursWypozycza` jest zerowane, jeśli **którykolwiek** warunek pada:
1. `var_members/kurs_wypożycza.value === true` (dokument z polskim „ż" w nazwie),
2. `kurs_uczestnicy/{email}.rokSzkoleniowki` istnieje i `Number(...)` daje skończoną liczbę,
3. rok == bieżący rok (2026) i dziś ≤ `2026-09-30` (dziś 10.07 → **okno czasowo otwarte**).

Dodatkowo `kursExpired = hasRok && dziś > {rok}-09-30` (tu: false).

### 2.3 Backend rezerwacji
- Handler `gearBundleReservationCreateHandler.ts:74-81`: kursant **przechodzi** bramkę roli
  (wyjątek `roleKey !== "rola_kursant"` dodany w commicie `6c453ba`); inne role spoza
  `memberRoleKeys` → 403 „Rezerwacja sprzętu wymaga roli Członek".
- `gear_bundle_service.ts` → `assertKursantRentalAllowed(...)` (`:236-252`), wspólny dla
  create i update:
  - flaga `kurs_wypożycza` ≠ true → `forbidden` „Rezerwacje dla kursantów są obecnie wyłączone.",
  - brak zwolnienia (okno zamknięte) → `kursant_window_closed`,
  - brak roku → `kursant_no_year` „Brak roku szkoleniówki na liście kursantów…".
- Rok czytany przez `resolveSchoolYear()` (`:190-207`) z `kurs_uczestnicy/{email(lowercase)}.rokSzkoleniowki`,
  parsowany przez `parseSchoolYear()` (`:177-182`).

## 3. ZNALEZIONY BUG: niespójne parsowanie `rokSzkoleniowki`

| Miejsce | Parsowanie | „2026" | „15.02.2026" | „2026/27" | ` 2026 ` (spacje) |
|---|---|---|---|---|---|
| `index.ts:417` (`/api/setup`) | `Number(raw)` | 2026 ✔ | **NaN ✘** | **NaN ✘** | 2026 ✔ (Number trymuje) |
| `gear_bundle_service.ts:177` (`parseSchoolYear`) | regex `(\d{4})` | 2026 ✔ | 2026 ✔ | 2026 ✔ | 2026 ✔ |

Skutek: jeśli w `kurs_uczestnicy/{email}.rokSzkoleniowki` wartość nie jest czystą liczbą
(np. data, rok z ukośnikiem, tekst z arkusza), to:
- `/api/setup` → `hasRok=false` → `windowOpen=false` → **`kursWypozycza=false`** →
  frontend wyłącza przyciski **we wszystkich kategoriach**, mimo że backend rezerwacji
  ten sam rok by zaakceptował.
- Objaw dokładnie odpowiada zgłoszeniu „kursant nie może rezerwować niczego".

## 6. Proponowana naprawa (zależnie od wyniku diagnozy)

### A — format roku (bug §3; warto naprawić NIEZALEŻNIE od wyniku)
1. Wyeksportować `parseSchoolYear` z `gear_bundle_service.ts` (albo przenieść do wspólnego
   modułu, np. `modules/equipment/bundle/` → helper współdzielony z `index.ts`).
2. W `index.ts:417` zamienić `Number(uSnap.data()?.rokSzkoleniowki)` na `parseSchoolYear(...)`
   — jedna definicja „roku szkoleniówki" w całej aplikacji.
3. `npm --prefix functions run build` + `lint`, deploy `--only functions`.

### B — flaga
Ustawić `var_members/kurs_wypożycza.value = true` (zweryfikować dokładną nazwę dokumentu
ze znakiem „ż"). Bez zmian kodu.

### C — dane uczestniczki
Uzupełnić `rokSzkoleniowki` w arkuszu kursu i przepuścić sync
(`appscript/kurs/uczestnicy_sync.gs`); jeśli sync nie przenosi tej kolumny — poprawić sync
(audyt 28.06 pkt 4, oznaczony tam jako KRYTYCZNY). Ewentualny jednorazowy backfill w Firestore.

### D — rola/status
Poprawić w arkuszu członków (źródło prawdy) i poczekać na `users.syncRolesFromSheet`
(albo odpalić task ręcznie).

### E — stary backend
Pełny deploy: `firebase use prod`, `firebase deploy --only functions` (predeploy zrobi
lint+build). Po deployu weryfikacja przez gcloud/konsolę, że funkcje mają nowy `updateTime`
(praktyka projektu po zmianach env/prod).

## 7. Weryfikacja po naprawie

1. `GET /api/setup` na koncie kursantki (albo `kursPreviewMode`) zwraca `kursWypozycza: true`,
   `kursExpired: false`.
2. W aplikacji: kafelek „Sprzęt" jako primary, sekcja „Moje rezerwacje" widoczna; przyciski
   „Rezerwuj" aktywne we **wszystkich** kategoriach.
3. Rezerwacja **kasku** + jednej innej kategorii przechodzi, bezpłatnie (koszt przekreślony —
   zwolnienie w oknie szkoleniówki), limity jak dla kandydata.
4. Kontrtest: flaga `kurs_wypożycza=false` → przyciski nieaktywne wszędzie, backend odrzuca
   z komunikatem „Rezerwacje dla kursantów są obecnie wyłączone."
5. Kontrtest okna: `rokSzkoleniowki=2025` → `kursExpired=true`, baner wygaśnięcia, brak rezerwacji.
6. Jeśli naprawiano A: test jednostkowy/ręczny `parseSchoolYear` dla wartości „2026",
   „15.02.2026", „2026/27", pustej i tekstowej — `/api/setup` i backend dają ten sam wynik.
