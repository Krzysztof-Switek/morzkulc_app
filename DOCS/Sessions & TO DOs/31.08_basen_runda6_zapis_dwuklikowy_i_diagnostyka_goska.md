### Gotcha (ponownie potwierdzony, już wcześniej znany problem)

Hash-only nawigacja (`#modul_6/...`) NIE wymusza pełnego reloadu dokumentu — to
tylko `hashchange`, przeglądarka celowo nie przeładowuje strony, więc już
zaimportowany moduł JS zostaje w pamięci taki, jaki był przy pierwszym wejściu.
Do tego SW cachuje pliki statyczne (`cache-first`) — `location.reload()` sam z
siebie NIE zawsze wystarcza. Testowanie nowego kodu po deployu wymagało:
`navigator.serviceWorker.getRegistrations()→unregister()` + `caches.delete()`
+ dopiero wtedy pełny reload. To DOKŁADNIE ten sam mechanizm co w sekcji 5.

## 4. Zgłoszenie: goska.witczak@gmail.com nie widzi/nie może dodać się jako instruktor

### Przebieg

1. User: "użytkownicy którzy nie mają prawa być instruktorami nie powinni widzieć
   przycisku 'Dodaj się jako instruktor'".
2. Sprawdzone w kodzie: ochrona JUŻ ISTNIEJE, w jednym miejscu, poprawnie
   zagatowana — `canBeInstructor = !isSauna && !isCancelled &&
   ctx?.session?.basenInstructor === true` (`basen_module.js:109`), przycisk
   dopisywany warunkowo (`:213-215`). Backend niezależnie blokuje to samo w
   `basenEnrollHandler.ts:92` (`admin.basenInstructor===true`).
3. User doprecyzował: **goska.witczak@gmail.com zgłasza coś odwrotnego** — że NIE
   MOŻE dodać się jako instruktor, mimo że w arkuszu ma `false` w kolumnie
   "Instruktor (kadra)".
4. Blokada: PERMISSION_DENIED przy próbie odczytu Firestore z tej maszyny (ADC
   wygasłe). User odświeżył logowanie: `gcloud auth application-default login`
   (na `admin@morzkulc.pl`) — **naprawione, działa ponownie**.
5. Odczyt `users_active` dla niej (skrypt jednorazowy, usunięty po użyciu):

```json
{
  "uid": "JMRIjuuu9ZP8rCa07nzXVKcnyd03",
  "email": "goska.witczak@gmail.com",
  "role_key": "rola_sympatyk",
  "admin": { "contributions": "2021-09-30", "hours": "39", "legNr": "631", "founder": false, "schoolYear": "" }
}
```

**Kluczowy fakt**: pole `admin.basenInstructor` W OGÓLE NIE ISTNIEJE w dokumencie
(nie `false` — brak klucza). Sync ze sheeta najwyraźniej nie zapisuje pola gdy
wartość jest fałszywa/pusta — ale funkcjonalnie wychodzi na to samo:
`undefined === true` → `false`, identyczny efekt jak jawne `false`.

6. Zweryfikowano też SAM DEPLOYNIĘTY kod (nie tylko plik źródłowy) — pobrany na
   żywo bajt-po-bajcie `basen_module.js` z `morzkulc-e9df7.web.app` zawiera
   dokładnie tę samą linię `canBeInstructor`. Kod na produkcji jest poprawny.

### Wniosek

**To NIE jest błąd w kodzie.** Zarówno frontend jak i backend poprawnie
odmawiają jej roli instruktora, bo w źródle prawdy (arkusz) ma `false`. Skoro
mimo to WIDZI przycisk — to musi być stary, zbuforowany bundle JS w jej
przeglądarce (dokładnie mechanizm z sekcji 3 wyżej: SW cache-first + JS moduł
trzymany w pamięci od dawna otwartej karty).

**Zalecenie dla niej** (przekazane userowi, NIE potwierdzone jeszcze przez nią):
1. Jeśli widzi baner "Dostępna nowa wersja aplikacji" → kliknąć "Odśwież teraz"
   (`hardReloadApp()` w `sw_update.js` — pełny unregister SW + clear cache +
   reload, gwarantowanie działa).
2. Jeśli baneru nie ma / zwykły refresh nie pomógł → całkowicie zamknąć
   kartę/appkę i otworzyć ponownie.
3. Ostateczność → wyczyścić dane strony w przeglądarce / reinstalacja PWA.

**Otwarte — do potwierdzenia w kolejnej sesji**: czy po odświeżeniu przycisk
faktycznie zniknął u niej. Jeśli NIE zniknie mimo pełnego resetu przeglądarki —
to byłby realny sygnał, że jednak jest gdzieś inna ścieżka pokazywania przycisku
(niesprawdzona, bo grep znalazł tylko jedno miejsce w kodzie) i trzeba by wrócić
do tematu.
