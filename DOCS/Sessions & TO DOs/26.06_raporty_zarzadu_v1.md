# 26.06 — Zakładki w panelu Zarząd + raport wypożyczonego sprzętu (analiza + plan)

## Cel

Rozbudować panel „Zarząd" (moduł `admin_pending`) o **dwie zakładki jak w Excelu**:
- **„Administracja"** — domyślnie aktywna po wejściu; zostaje dokładnie to, co jest
  teraz (oczekujące godzinki/imprezy, ostrzeżenia synców sprzętu, martwe joby,
  ujemne salda itd.).
- **„Raporty"** — nowa; na start jeden raport: **aktualnie wypożyczony sprzęt**, z
  drop-downem zakresu czasu i checkboxami kategorii.

## Decyzje (uzgodnione z użytkownikiem)

- Zakresy w drop-down = **okna kroczące do dziś**: „Aktualnie wypożyczony"
  (domyślne) · „Ostatni miesiąc" (30 dni) · „Ostatni semestr" (6 mies.) ·
  „Ostatni rok" (12 mies.) · „Zakres dat" (od–do).
- Filtr sprzętu = **checkboxy kategorii** (multi-select): Wszystkie (domyślnie) ·
  Kajaki · Wiosła · Kamizelki · Kaski · Rzutki · Fartuchy.

## Plan implementacji

### Backend — `GET /api/admin/reports/gear-rentals`
1. **Nowy handler** `functions/src/api/getAdminGearRentalsHandler.ts` (deps + gating
   admina jak `getAdminPendingHandler`):
   - Params: `range = current|month|semester|year|custom`; `from`,`to` dla `custom`.
   - Wylicz `rangeStart`/`rangeEnd`: current→dziś–dziś; month→−30 dni;
     semester→−6 mies.; year→−12 mies.; custom→walidacja.
   - Zapytanie z nakładaniem, bez indeksu złożonego:
     `gear_reservations.where("endDate", ">=", rangeStart).orderBy("endDate").limit(1000)`,
     potem w pamięci `status === "active" && startDate <= rangeEnd`.
   - Nazwy: unikalne `userUid` → `db.getAll(...)` → mapa uid→„Imię Nazwisko"
     (fallback nickname/email; pomocnik jak `fullNameFromUser` z `getKlubInfoHandler.ts`).
   - Wiersze (per rezerwacja): `{ userName, userEmail, startDate, endDate,
     items:[{category, categoryLabel, number, label}], costHours }`.
   - Odpowiedź `{ ok, range:{from,to}, count, rows }`.
2. **`functions/src/index.ts`**: eksport `getAdminGearRentals = onRequest(...)` z deps
   jak `getAdminPending`.
3. **`firebase.json`**: rewrite `/api/admin/reports/gear-rentals` → `getAdminGearRentals`.

# v2 — Launcher kafelkowy (~20 raportów) + poprawki raportu sprzętu

## Cel
Przy ~20 raportach nie mogą renderować się jeden pod drugim. Wzorzec
**launcher → szczegół**: na karcie Raporty widać **wszystkie** raporty jako
**kafelki pogrupowane w kategorie + szukajka**, ale dane renderuje **tylko jeden
naraz** po kliknięciu; powrót „← Raporty". (Wybór UX użytkownika: kafelki + szukajka.)

## Architektura — rejestr raportów
Dodanie raportu = **nowy plik + jeden wpis w rejestrze**. Deskryptor:
`{ id, category, label, description, render({container, ctx}) }`.

Nowe pliki (`public/modules/raporty/`):
- `reports_panel.js` — `renderReportsPanel({container, ctx})`: stan launcher/szczegół.
  - **Launcher**: pole `🔍 szukaj` (filtruje kafelki po label+description), kafelki
    pogrupowane wg `category` (nagłówek + siatka), klik → `openReport(id)`.
  - **Szczegół**: `[← Raporty]` + tytuł + `descriptor.render(...)`; powrót → launcher.
  - Start zawsze od launchera; żaden raport nie ładuje danych dopóki nieotwarty.
- `registry.js` — eksport `REPORTS` (na start: gear-rentals).
- `gear_rentals.js` — raport „Wypożyczony sprzęt": logika przeniesiona z
  `admin_pending_module.js` + dwie poprawki niżej.

`admin_pending_module.js`: panel Raporty → punkt montażu `<div id="reportsPanel">`,
przy leniwym wejściu w zakładkę woła `renderReportsPanel(...)`; usuwamy stamtąd
inline'owy markup/wiring raportu.

`base.css`: style launchera `.reportLauncher/.reportSearch/.reportCatHead/
.reportGrid/.reportTile/.reportDetailHead` (siatka responsywna, 1–2 kol. mobile).
Style `.reportTable/.reportControls/.reportCats` z v1 zostają.

## Poprawki raportu sprzętu (gear_rentals)
1. **Liczba pojedyncza w pozycjach** (poprawka błędu z v1): zamiast „Kajaki 11" →
   **„Kajak 11"**. Mapa kategoria→l.poj. po stronie klienta:
   `kayaks→Kajak, paddles→Wiosło, lifejackets→Kamizelka, helmets→Kask,
   throwbags→Rzutka, sprayskirts→Fartuch`. Checkboxy filtra zostają w l.mnogiej.
2. **Selektor użytkownika** (obok zakresu): pole szukania, **domyślnie wszyscy**;
   filtruje wiersze po **nazwisku / ksywie / mailu** (substring), łączone z filtrem
   kategorii; `<datalist>` z użytkownikami pobranego zbioru = autouzupełnianie.
   Filtr po stronie klienta na pobranych wierszach.
   - Backend (mały redeploy): w `getAdminGearRentalsHandler.ts` dodać `userNick`
     do wiersza (handler i tak czyta dok. użytkownika), by szukać po ksywie także
     gdy user ma imię/nazwisko.
